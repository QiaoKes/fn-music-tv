# 收藏与播放队列管理

## Goal

让电视端用户可以在播放页快速收藏当前歌曲、从首页进入收藏列表，并直接清理当前播放队列中的指定歌曲，减少在遥控器操作下返回曲库查找或重建队列的步骤。

## Background

- 播放器当前在普通队列模式下使用“播放模式 -> 上一首 -> 播放/暂停 -> 下一首 -> 播放队列”的显式遥控器焦点链；随机漫游会隐藏播放模式和队列入口。
- 右侧播放队列当前展示序号、标题、歌手和当前播放标记，支持选择歌曲，但没有删除动作。
- 首页当前是一条横向卡片列表，顺序为“随机漫游 -> 最近 12 个歌单 -> 全部歌单”；本次按用户要求拆成两行。
- 客户端已有按账号 namespace 持久化播放队列和设置的 Room 数据库，但没有收藏实体、收藏仓库或已封装的收藏 API。
- 用户要求收藏跨设备同步；服务端数据是收藏状态的唯一事实来源，客户端需要调用 TrimMusic 对应 API，并可保留账号隔离的本地缓存以改善启动和断网展示。
- `docs/API.md` 已确认收藏契约：`POST /favorite-track/create`、`POST /favorite-track/delete` 使用 JSON `trackGUID`，`GET /favorite-track/list` 返回分页的 `TrackWithFavoriteAndAccess`，支持 `favoriteAt,desc` 排序；常规歌曲响应也包含 `isFavorite`。

## Requirements

### R1. 播放器收藏按钮

- 在普通播放控制条最左侧增加红心图标按钮，位于播放模式按钮左侧。
- 按钮显示当前歌曲是否已收藏；未收藏为轮廓心形，已收藏为红色实心心形。
- 按下按钮切换当前歌曲的收藏状态，并立即更新视觉与无障碍语义。
- 红心、播放模式、传输按钮和播放队列之间必须保持确定的 D-pad 焦点路径，且触摸点击仍只触发一次。
- 随机漫游中仍显示红心按钮；播放模式和队列入口继续隐藏，红心接入漫游现有的传输/退出焦点链。
- 没有可播放歌曲时不得创建无效收藏记录。

### R2. 右侧播放队列删除

- 普通播放队列中的每一行提供独立删除动作，视觉参考用户提供的行尾 `X`。
- 删除动作必须删除用户选中的队列 occurrence，而不是仅按歌曲 ID 删除第一个同名项。
- 删除后立即刷新序号、当前播放标记、队列数量与持久化快照。
- 删除非当前项时继续播放当前歌曲；删除当前项时按 Media3 队列语义平滑切换到可用的下一项，末尾则回退到上一项；删除最后一项后停止播放并显示空队列。
- 删除后若原焦点目标仍存在则保留焦点；若被删项消失，则优先聚焦新的当前歌曲，否则聚焦相邻可用行；空队列不保留悬空焦点。
- 随机播放模式下删除后必须重建有效的随机顺序，不能保留已删除 ID 或让异步确认覆盖新队列。
- 随机漫游的一项临时队列不支持从右侧队列删除，因为随机漫游当前不显示队列入口。

### R3. 首页收藏入口与收藏列表

- 首页第一行只放“随机漫游”和“收藏”两个并列入口，不在该行混入歌单。
- 首页第二行从歌单卡片开始，保留最近 12 个歌单的横向浏览，并以“全部歌单”作为末尾入口。
- 收藏入口显示红心视觉，并进入独立的收藏歌曲列表。
- 第一行和第二行之间提供明确的 D-pad 上下焦点路径；返回首页时恢复此前所在行、卡片焦点和第二行滚动位置。
- 收藏列表沿用现有歌曲集合页的加载、焦点、分页/滚动和开始播放交互；从其中选择歌曲可建立正常播放队列并进入播放器。
- 收藏列表返回首页时恢复首页原来的焦点和滚动位置。
- 取消收藏后，收藏列表应及时移除对应歌曲；空收藏列表显示稳定的空状态。

### R4. 收藏数据一致性

- 收藏按登录账号隔离，切换账号后不得看到另一账号的收藏。
- 收藏必须通过 TrimMusic API 跨设备同步，并跨应用重启保留。
- 服务端是收藏状态的唯一事实来源；客户端可缓存足够的歌曲快照以稳定渲染，但联网刷新必须与服务端收敛。
- 收藏列表通过 `GET /favorite-track/list?page=<n>&size=50&sort=favoriteAt,desc` 加载；收藏和取消收藏分别调用 `POST /favorite-track/create` 与 `POST /favorite-track/delete`，请求体为 `{ "trackGUID": "<guid>" }`。
- 客户端歌曲 DTO/领域模型必须保留服务端返回的 `isFavorite`，播放器初始红心状态不得靠单独猜测或仅查询本地记录。
- 收藏写入成功后立即更新播放器和收藏列表；写入失败时恢复服务端确认状态并显示可重试错误，不能保留仅本机可见的假收藏。
- 播放收藏歌曲时仍通过现有播放准备路径验证歌曲是否可播放。
- 同一歌曲重复收藏必须幂等，取消收藏不存在的歌曲也不得失败。

## Acceptance Criteria

- [ ] 普通播放器左侧显示红心按钮，按钮可用遥控器和触摸切换当前歌曲收藏状态，状态立即可见。
- [ ] 已收藏歌曲在离开播放器、重启应用、重新登录同一账号及另一设备登录同一账号后仍保持收藏状态。
- [ ] 不同账号的收藏互相隔离；客户端刷新后与服务端收藏状态收敛。
- [ ] 收藏 API 失败时不会留下错误的本地收藏状态，并提供明确、可重试的错误反馈。
- [ ] 首页第一行仅包含“随机漫游”“收藏”，第二行从歌单开始并以“全部歌单”结束；收藏可打开独立歌曲列表。
- [ ] 收藏列表能显示收藏歌曲、处理空状态、取消收藏后的更新，并能从选中歌曲开始正常播放。
- [ ] 右侧队列每行可删除指定 occurrence，删除后队列 UI、播放位置、随机顺序和持久化快照一致。
- [ ] 删除当前歌曲、队尾歌曲和最后一首歌曲时行为稳定，无崩溃、空白焦点或陈旧播放状态。
- [ ] 新增交互符合现有 Android TV 显式焦点、触摸单次触发和动态目标消失后的焦点迁移约定。
- [ ] 单元测试覆盖收藏幂等/账号隔离/持久化、队列删除索引与随机模式更新、首页及播放器焦点投影。

## Out of Scope

- 收藏歌单、专辑或艺术家。
- 收藏排序、搜索、批量管理和导入导出。
- 在随机漫游中打开或删除临时队列。
- 修改 TrimMusic 服务端实现；本任务调用服务端已有收藏 API。若服务端实际未提供所需契约，必须先确认或补充服务端范围后再实现。
