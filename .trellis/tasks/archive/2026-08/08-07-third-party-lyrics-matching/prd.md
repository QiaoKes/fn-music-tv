# 第三方歌词匹配模块与播放器接入

## Goal

用可独立维护的原生 Kotlin 歌词匹配模块为播放器增加高置信度第三方歌词能力：默认优先读取已匹配缓存或在线聚合多个来源，无法得到可用结果时无缝回退飞牛 `lyric/list`，使电视端在可接受的网络延迟内稳定展示正确的同步原文和译文。

## Background

- 当前 `MusicRepository.currentLyrics(trackGuid)` 只调用飞牛歌词接口，选择 preferred/LRC 内容后交给现有解析器（`core/data/src/main/kotlin/com/fnmusic/tv/core/data/repository/MusicRepository.kt:112-118,356-361,462-487`）。
- 当前 `Track` 已包含标题、歌手、专辑和时长，覆盖第三方歌词搜索与候选评分需要的核心元数据（`core/model/src/main/kotlin/com/fnmusic/tv/core/model/Models.kt:45-56`）。
- 当前播放 `MediaItem` 已携带标题、歌手和专辑，`NowPlayingIdentity` 尚未携带专辑和时长；歌词与完整元数据并行加载（`core/playback/src/main/kotlin/com/fnmusic/tv/core/playback/PlaybackController.kt:1093-1105`、`app/src/main/java/com/fnmusic/tv/NowPlayingPresenter.kt:189-208`）。
- 当前 `LyricLine.texts` 支持同一时间点显示多行文本，播放器布局已经按双语歌词预留自然换行空间；YRC 解析器目前只保留行级开始时间并移除逐字时间戳（`core/model/src/main/kotlin/com/fnmusic/tv/core/model/lyric/LrcParser.kt:10-23,81-125`）。
- LDDC 最新 `flutter` 分支把匹配算法和无 UI 运行时拆成纯 Dart 包，但未发布为可依赖制品；本项目是原生 Kotlin Android，因此本任务移植其算法和必要协议，不嵌入 Python、Dart 或 Flutter 运行时。
- 本项目与 LDDC 均采用 GPL-3.0；移植或改写受版权保护的实现时必须保留来源和许可证说明。

## Requirements

### R1. 独立歌词模块

- 新增 `:core:lyrics` Gradle 模块，使用 Kotlin/JVM 17，不依赖 Android UI、飞牛会话或播放器实现。
- 模块集中拥有第三方歌词领域模型、文本规范化、标题/歌手/专辑/时长评分、歌曲版本冲突识别、歌词行对齐、来源接口、匹配编排和来源响应解析。
- `core:data` 只负责把项目 `Track` 映射为模块请求、提供命名空间缓存适配，并把模块结果映射为 `CurrentLyrics`；UI 不解析第三方原始响应。
- 所有来源共享一个明确的 `LyricsSource` 契约和统一结果/错误模型，新增或修复单个来源不得要求修改匹配算法或播放器 UI。

### R2. 第三方歌词源

- 默认并发搜索 QQ 音乐、酷狗音乐、网易云音乐；LRCLIB 因实测搜索延迟过高已移除。单个来源不可用、超时、返回空结果或协议变化不能使其他来源失败。
- 来源实现参考 LDDC `flutter` 分支提交 `1ffa0e25426e654376e5d55d854b135ae601f43b` 的请求、匹配、解析和响应契约，并为每个来源保存去敏测试夹具。本次行级展示热路径优先使用来源可直接返回的 LRC/YRC 文本，不宣称支持专有 QRC/KRC 二进制解密。
- 第三方 HTTP 客户端与飞牛会话客户端完全隔离，不发送飞牛 token、访问码、Cookie、服务器地址或用户标识。仅允许来源协议要求的匿名设备标识，并不得记录完整标识或敏感请求体。
- 优先使用 HTTPS。酷狗遗留 HTTP 搜索仅在 HTTPS 兼容路径不可用且现有网络安全策略明确允许时使用；调用必须匿名、限域并可独立关闭。
- 在线匹配开启时，歌词解析顺序固定为“有效第三方匹配缓存 → 第三方在线匹配 → 飞牛歌词”；第三方没有高置信度结果、全部来源失败/超时、响应无效或歌词为空时回退飞牛，取消和过期 revision 不得触发回退。
- 在线匹配关闭时完全跳过第三方缓存读取和网络请求，直接沿用现有飞牛 `lyric/list`、重试和离线缓存链路；飞牛 DTO/API 必须保留为正式兜底实现。

### R3. 高置信度匹配

- 搜索关键词优先使用“歌手 - 标题”，无可用结果时对同一来源回退为标题；缺少标题时不自动猜测歌词。
- 候选评分至少覆盖 Unicode/全半角规范化、标题、歌手集合/别名、专辑、时长和 `Instrumental`/伴奏/Off Vocal/Live/Remix 等版本信息。
- 普通歌曲不得自动采用明确的伴奏候选；候选与本地时长均已知且差异超过 4 秒时不得自动采用。
- MVP 初始最低综合分为 80；标题分低于 50、版本冲突或关键元数据明显矛盾的结果必须拒绝。阈值集中配置并由测试数据校准，不分散为来源私有常量。
- 歌曲正确性优先于歌词丰富度。只有综合分差不超过 5 分的候选才允许用逐字、译文完整度和来源优先级打破平局。
- 多个来源返回一致的标题、歌手和相近时长时提高置信度；没有高置信度结果时返回“无歌词”，不得用低分候选填充播放器。

### R4. 实时性、并发与取消

- 缓存未命中时并发搜索来源，并对每个网络请求设置可取消的独立超时；整体匹配有界，任何路径不得沿用 LDDC 的 30 秒 UI 等待上限。
- 强匹配可在短暂聚合窗口后提前完成；典型冷请求应只消耗各来源一次搜索和最终候选一次歌词获取。歌词为空时最多尝试两个后备候选。
- 切歌、账号切换、缓存清理和 Presenter revision 变化必须取消或拒绝旧匹配结果；旧歌曲结果不能进入当前播放器状态。
- 复用长生命周期 OkHttp 连接池，不为每首歌创建客户端。评分、解密和解析不得运行在主线程。
- 目标性能为：有效缓存命中 P95 小于 50 ms；正常网络下冷匹配 P50 小于 1.2 s、P95 小于 3 s。目标以测试/诊断记录验证，不把网络波动伪装成算法耗时。

### R5. 缓存与离线行为

- 复用项目的账号命名空间、LRU、single-flight、取消和持久缓存原则；缓存身份至少包含 namespace、飞牛 track GUID、规范化元数据指纹和匹配协议版本。
- 成功匹配后立即保存已经选择并解析的第三方歌词结果，而不是各来源的完整搜索响应；下次播放同一元数据指纹必须直接命中，不得重复搜索或获取歌词。
- 有效歌词可长期复用；“未找到”只允许短期负缓存，避免错误空结果永久阻止后续恢复。
- 网络不可用时优先返回当前元数据指纹对应的有效持久缓存；没有缓存时保持现有可重试失败/无歌词语义。
- 第三方匹配缓存与现有飞牛 `cache_lyric` 分开保存，使开关切换和飞牛回退不会覆盖已匹配结果；清理歌词/全部可清理缓存时两者必须同时失效。
- Room 升级到 v3：新增独立第三方匹配缓存表，并保留现有飞牛缓存数据；迁移必须有 schema 和升级测试。

### R6. 原文与译文展示

- 模块结果分别保存原文、译文和可选罗马音轨道；播放器默认只组合原文和译文。
- 每个时间组原文排第一，匹配到的译文紧随其后；无译文时只显示原文，不显示空行、占位或罗马音。
- 译文时间轴使用 LDDC 的歌词行匹配思路对齐，不得仅凭相同数组下标拼接；重复行、空行和时间轻微偏移必须保持稳定顺序。
- 静态歌词继续使用现有静态文本回退。行级同步和现有播放器滚动/高亮行为保持兼容。
- 本任务保留逐字时间信息的模块模型和解析能力，但 UI 仍按行高亮；逐字卡拉 OK 渲染不作为本次验收条件。

### R7. 播放链路接入

- `NowPlayingIdentity` 或等价的当前播放请求必须携带可用的标题、歌手、专辑和时长，使歌词匹配无需串行等待飞牛完整元数据请求；缺失字段允许由并行元数据结果补充后重试一次。
- `NowPlayingPresenter` 继续拥有当前歌曲资源并发、revision 校验、自动/手动重试和加载期间保留上一首可显示歌词的现有契约。
- 第三方歌词成功直接映射到 `Ready`；其余非取消终态先调用飞牛歌词，只有飞牛也无歌词或失败后才映射为现有 `Absent`、`RetryableFailure`，不得产生无限加载。
- 登录、退出、切换账号和清理缓存必须关闭/清理对应歌词请求与缓存状态，不影响音频播放、封面和队列。

### R8. 在线匹配设置

- 设置页新增一个真实的 TV 可聚焦二元开关“在线歌词匹配”，默认开启；旧版本升级和新账号都必须得到开启值。
- 该设置沿用 `AppPreferencesState` 和 `account_state` 的账号命名空间持久化，不同飞牛账号可有不同选择。
- 关闭后直接使用飞牛歌词且不删除已有第三方匹配缓存；重新开启后仍可复用有效匹配缓存。
- 修改开关后，当前歌曲立即取消旧歌词请求并按新策略重新加载，不要求重启应用；迟到结果仍受 namespace、media 和 revision 校验保护。
- 开关必须使用 `Modifier.toggleable`/等价 TV 可访问语义、稳定焦点邻居和明确选中状态，不用普通文本按钮模拟 ON/OFF。

## Out Of Scope

- 除“在线歌词匹配”总开关外，本任务不增加单独歌词源设置、来源排序、手动候选选择、歌词编辑、歌词下载或写回音频标签。
- 本任务不实现音频指纹、声学对齐、AI 翻译或缺失译文的机器翻译。
- 本任务不实现逐字卡拉 OK 绘制、逐字渐变或桌面歌词。
- 本任务不新建 NAS 旁路服务；来源协议直接由独立 Kotlin 模块承担，但接口边界允许未来替换为服务实现。
- 本任务不改变播放队列、音频缓冲、收藏、封面或整体播放器布局。

## Acceptance Criteria

- [ ] AC1: Gradle 存在独立 `:core:lyrics` 模块，`app/core:data/core:playback` 只通过公开契约接入；模块不依赖 Android UI 或飞牛认证客户端。
- [ ] AC2: 可控测试证明 QQ、酷狗、网易搜索并发运行；任一来源超时/失败时仍能选择其他高置信度来源，所有来源失败时在有界时间内结束。
- [ ] AC3: 参数化匹配测试覆盖同名歌曲、多歌手/别名、专辑差异、时长边界、Live/Remix/伴奏版本、全半角和中日韩文本；低于阈值或版本冲突结果不会自动展示。
- [ ] AC4: 候选分差大于 5 时始终选择元数据分更高的歌曲；分差不超过 5 时才按原文逐字/译文完整度和来源顺序打破平局。
- [ ] AC5: 在线匹配开启时按“第三方缓存 → 在线匹配 → 飞牛歌词”执行；高置信度第三方结果不调用飞牛，第三方无匹配、超时、全部失败、无效响应或空歌词时调用飞牛并正确展示其结果。
- [ ] AC6: 有译文的歌词在同一时间组显示“原文在上、译文在下”；无译文时只显示原文；罗马音默认不显示，重复/错位行不造成跨行串配。
- [ ] AC7: A → B → A 快速切歌并逆序完成网络响应时，只允许最新 revision 的歌词显示；取消结果不写入失效 namespace，也不覆盖有效缓存。
- [ ] AC8: 同一歌曲第二次播放命中有效第三方缓存且不发起任何第三方请求；元数据指纹/协议版本变化会重新匹配；短期无结果缓存到期后可恢复。
- [ ] AC9: 去敏 provider 夹具覆盖搜索、歌词获取和本次热路径使用的文本解析；测试日志、异常和缓存不包含飞牛凭据或完整匿名设备标识。
- [ ] AC10: 相关单元测试、`assembleSideloadDebug`、Android lint 和现有播放器测试通过；性能诊断记录缓存命中与至少一组冷匹配耗时，并与目标对照。
- [ ] AC11: README“特别感谢”包含 `https://github.com/chenmozhijin/LDDC` 及准确的参考说明，相关移植文件保留 GPL-3.0 来源声明。
- [ ] AC12: 设置页存在默认开启的“在线歌词匹配”TV 开关；关闭时第三方缓存和网络调用均为零、直接使用飞牛歌词，重新开启后已有匹配缓存仍可直接复用。
- [ ] AC13: Room v2 → v3 迁移保留账号、队列、设置和飞牛歌词缓存，为旧账号写入在线匹配默认开启值；匹配缓存清理、账号隔离和容量回收测试通过。

## Technical Notes

- LDDC 的仓库调研和移植边界记录在 `research/lddc-portability.md`。
- 网络源是可变外部依赖。验收以去敏确定性夹具为主，真实 API 冒烟为独立诊断，不让偶发网络波动破坏默认离线测试链。
- 初始阈值和性能数字是 MVP 工程目标，必须集中配置并在后续真实曲库样本上校准；本任务不承诺未经验证的覆盖率百分比。
