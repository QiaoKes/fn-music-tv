# 修复遥控器在线匹配并替换歌词解析与展示

## Goal

修复 Android TV 设置页中“在线歌词匹配”无法通过遥控器确认键切换的问题，并以 `accompanist-lyrics-core` 和 `accompanist-lyrics-ui` 统一歌词解析、逐字高亮和跟随滚动。播放器需要在单语、双语和逐字歌词下保持紧凑、清晰、适合电视距离观看。

## Confirmed Evidence

- `SettingsCheckbox` 曾将 `focusable()` 和 `toggleable()` 分成两个节点，导致焦点节点不是确认键的激活节点；现有偏好持久化与歌词重载链路无需重构。
- 播放器当前只渲染当前行和下一行，不是真正的滚动列表；固定高度槽位也放大了单语和双语歌词之间的视觉距离。
- 歌词解析重复存在于 `core/lyrics/.../LyricsTextParser.kt` 和 `core/model/.../lyric/LrcParser.kt`，且线上源仍混用自写 LRC/YRC 解析。
- 当前线上源为 QQ 音乐、酷狗音乐和网易云音乐。网易云已经能返回 YRC；QQ 当前接口仍只返回 LRC；酷狗当前请求的是多轨 LRC。
- `accompanist-lyrics-core` 内置 LRC、YRC 和 KRC 解析，但不包含 QRC。没有找到适合本项目直接引入的、维护中的 Kotlin/JVM QRC 解析库。
- 模拟器缓存中的 `min~眠~` 原始歌词确实包含 `世(よ)` / `世（よ）` 一类日文括号注音；解析器替换本身不会自动清理它。

## Requirements

- R1: “在线歌词匹配”的焦点节点必须直接响应 Android TV 遥控器确认键，一次按键只切换一次，并沿用现有偏好持久化和歌词重载链路。
- R2: 同一设置的触摸/点击行为必须继续可用，且不能因遥控器兼容处理而重复切换。
- R3: 使用 `accompanist-lyrics-core` 的歌词模型作为解析、匹配到 UI 的唯一运行时歌词模型。删除 `LyricsTextParser`、`LrcParser/LyricParser`、旧 `TimedLyrics* / SourceLyrics` 模型及其旧测试；项目只保留来源网络传输、候选元数据和缓存外壳，不再维护平行的歌词行/逐字模型。
- R4: 启用网易云 YRC、QQ 音乐 QRC、酷狗 KRC，并为三者保留普通 LRC 回退。YRC/KRC 使用库内置解析器；QRC 使用经批准的、隔离且有 fixture 测试的 Kotlin 适配器，并注册到库的解析接口中。
- R5: 使用 `accompanist-lyrics-ui` 替换当前双行歌词窗口，提供真正的多行列表、播放跟随滚动、当前行强调、逐字高亮和翻译同行分组；删除 `currentAndNextLyricIndices`、旧歌词行 Composable、旧高亮/槽位/动画 helper 及只覆盖旧 UI 的测试，不得复制或 fork 该库实现。
- R6: 歌词样式必须适合电视：单语与双语行距紧凑，原文和翻译层级清晰，翻译字号不能过小，长行可换行；歌词窗口需要充分利用底部控制栏上方的安全区域，并让当前行下方保留更多上下文，海报和 CD 两种播放器样式行为一致。
- R7: 歌词列表不得抢占遥控器焦点或破坏播放器现有方向键导航；歌词点击等触摸交互不应成为 TV 主交互路径。
- R8: 只有本地歌曲与候选歌曲时长均已知，且绝对差值不超过 2,000 ms 时，才允许使用该候选的逐字时间和逐字高亮。
- R9: 候选按以下字典序排序：带翻译/翻译覆盖更完整、可用逐字同步、时长差更小、来源顺序网易云 > QQ 音乐 > 酷狗；既有元数据匹配阈值仍作为前置过滤条件。
- R10: 普通逐行歌词的时长差必须不超过 5,000 ms。逐字候选超过 2,000 ms 但不超过 5,000 ms 时，移除逐字时间后仍可作为逐行候选；超过 5,000 ms 的候选直接排除。
- R11: 对展示文本中的日文括号注音（半角或全角括号）隐藏括号及其读音，只保留正文；清理后必须保留剩余文字的有效行时间和逐字时间，不实现 ruby 注音。
- R12: 在 `README.md` 现有 `## 特别感谢` 下致谢并链接 `accompanist-lyrics-core` 与 `accompanist-lyrics-ui`，不增加应用内致谢页面或设置项。
- R13: 解析器和匹配策略变化后必须提升歌词匹配缓存协议版本，避免旧缓存绕过新格式、翻译优先级与 2/5 秒门槛。

## Acceptance Criteria

- [x] 聚焦“在线歌词匹配”后，一次遥控器确认键只切换一次，界面状态和持久化值同步更新。
- [x] 触摸/点击同一设置仍只切换一次；相关 TV 焦点与 Compose 测试通过。
- [x] 生产环境中的 FnMusic、本地与三个线上源均通过 `accompanist-lyrics-core` 适配层解析，不再调用现有通用正则解析器。
- [x] 旧解析文件、旧 `TimedLyrics* / SourceLyrics` 模型、旧双行歌词 UI/helper 和仅服务旧实现的测试已删除；全仓搜索不存在失效引用或第二套歌词时间轴实现。
- [x] 网易云 YRC、QQ QRC、酷狗 KRC fixture 均能生成有效逐字时间；各来源普通 LRC 回退仍可用。
- [x] 两种播放器样式都展示真实多行歌词列表，并在播放跨行时平滑滚动，使当前行保持可见。
- [x] 当前行、逐字进度、翻译、紧凑行距和长行换行在电视距离下清晰可读，歌词区域不抢遥控器焦点。
- [x] 已知时长差 `<= 2,000 ms` 的逐字候选可以逐字高亮；差值更大或任一时长未知时只能逐行显示。
- [x] 排序测试证明：翻译优先于逐字同步，逐字同步优先于更小时长差，最后由网易云/QQ/酷狗顺序解开平局。
- [x] 普通逐行候选仅在时长差 `<= 5,000 ms` 时可用；逐字候选在 `2,001..5,000 ms` 内会稳定降级且不残留逐字高亮，`> 5,000 ms` 时被排除。
- [x] `世(よ)` 与 `世（よ）` 等 fixture 均只显示正文，清理后时间轴仍合法。
- [x] 缓存协议提升，旧的已匹配歌词不会跳过新解析和选择规则。
- [x] `README.md` 的 `## 特别感谢` 正确致谢并链接两个开源库。
- [x] 核心单元测试、app 单元测试、lint、构建及 Android 16 TV 模拟器验证全部通过；验证完成后模拟器保持运行。

## Out of Scope

- 增加网易云、QQ 音乐、酷狗以外的新歌词来源。
- 改变既有搜索开关、元数据最低匹配阈值、普通逐行歌词的整体容差或数据库架构。
- fork/复制两个开源库，或引入 Web/JavaScript 运行时解析 QRC。
- 实现 ruby、小字注音、罗马音切换或新的歌词设置页面。
- 新增应用内“特别感谢”页面。

## Technical Constraints

- 网络请求、QQ QRC 解包和酷狗 KRC 解密/解压属于来源适配层；歌词语法解析统一交给库及唯一的 QRC 插件。
- QRC 插件只处理 QQ 原生 QRC 语法，不扩展成第二套通用 LRC/YRC/KRC 解析器。
- 除 SDK 类型无法直接持久化时所需的私有 cache DTO 外，不新增与 SDK `line/syllable/translation` 结构重复的公共或运行时模型；cache DTO 不参与匹配和 UI 业务逻辑。
- `accompanist-lyrics-ui` 必须通过公开 API 配置 TV 样式与非聚焦行为，不修改依赖源码。
- 2,000 ms 规则只控制逐字信息是否可信，不应单独导致 5,000 ms 范围内可用的逐行歌词被丢弃。
