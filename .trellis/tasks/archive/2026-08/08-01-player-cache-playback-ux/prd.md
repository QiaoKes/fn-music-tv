# 播放器体验与缓存优化

## Goal

在 Android TV 遥控器场景中减少重复网络请求和可感知等待，补齐漫游连续播放、播放队列、常见循环模式、页面初始焦点与双击返回桌面，并系统性修正播放状态切换中的竞态和边界错误。

## Background

- 用户反馈歌手、专辑、歌单等页面每次进入都会重新请求 API，切页体验不流畅。
- 用户希望图片命中缓存更快，并质疑当前音频与图片 3:1 的持久缓存比例是否适合局域网音乐播放。
- 用户反馈漫游歌曲播完后不会自动播放下一首。
- 当前播放页缺少队列入口、队列展示和顺序/列表循环/单曲循环/随机播放等常用模式。
- 用户提供的播放器操作条与队列参考图：

## Confirmed Facts

- `MusicRepository` 已把列表、详情、歌词写入 Room，但正常命中仍先访问网络，只有网络失败才读取本地数据，因此重新进入页面仍会调用 API（`core/data/src/main/kotlin/com/fnmusic/tv/core/data/repository/MusicRepository.kt:232`、`:263`）。
- 图片已有 24 MiB 进程内原始字节 LRU 和磁盘缓存，但同图并发请求未合并，Bitmap 解码结果也只随当前 Composable 保存（`MusicRepository.kt:49`、`:166`；`app/src/main/java/com/fnmusic/tv/ui/AuthenticatedApp.kt:1008`）。
- 默认 512 MiB 缓存中，音频占 75%（384 MiB），图片占 25%（128 MiB）；Media3 `SimpleCache` 会持久保留已播放到的音频分片，而不只是当前流式缓冲（`core/model/src/main/kotlin/com/fnmusic/tv/core/model/preferences/Preferences.kt:5`；`core/playback/src/main/kotlin/com/fnmusic/tv/core/playback/PlaybackService.kt:43`）。
- 漫游通过单元素 Media3 队列播放；下一首只由播放页按钮触发，播放器结束事件没有连接漫游 API，因而自然播完必然停住（`PlaybackController.kt:159`、`:166`；`AuthenticatedApp.kt:1186`）。
- 正常队列最多维护 250 首滑动窗口，但 `PlaybackUiState` 只暴露数量和当前位置，没有可供队列面板渲染的条目，也没有播放模式状态（`PlaybackController.kt:36`、`:248`）。
- 滑动队列从头部淘汰后没有推进 `firstPage`，从尾部淘汰后没有回退 `lastPage`，反向浏览会跳过刚被淘汰的页面（`core/model/src/main/kotlin/com/fnmusic/tv/core/model/playback/Playback.kt:79`、`:106`）。
- 漫游窗口由 Compose 保存，而实际队列与冻结队列由播放控制器保存；播放普通歌曲、Activity 重建或退出漫游时，两套状态可能分歧，且退出后的恢复队列未立即持久化（`AuthenticatedApp.kt:140`、`PlaybackController.kt:159`、`:168`）。
- 上一首/下一首切换时，Media3 可短暂暴露“新 `currentMediaItem` + 旧聚合 `mediaMetadata`”，而当前投影恰好混用两者；封面和歌词又都是同键一次性加载，失败后不会重试（`PlaybackController.kt:248`；`AuthenticatedApp.kt:1008`、`:1047`）。
- 本地飞牛音乐 APK 暴露 `sequence/listLoop/singleLoop/shuffle`、完成原因、当前队列项、随机顺序和漫游窗口等持久播放会话字段；本地网易云音乐 TV APK 使用播放器内右侧队列浮层，并在打开后定位当前歌曲。参考证据只用于确定行为，不复制代码或资源（`research/playback.md`、`research/tv-ux.md`）。
- 当前根页面未拦截 Back，第一次返回就离开 Activity；新开的网格页没有统一的首项焦点请求（`AuthenticatedApp.kt:140`、`:570`）。
- 项目规范要求漫游前后切歌单飞，退出漫游恢复冻结的普通队列并保持暂停；TV 按钮必须使用显式方向焦点图（`.trellis/spec/frontend/android-tv-interaction.md`）。

## Requirements

### R1. 元数据与图片缓存

- 同一服务器与账号命名空间内，歌手、专辑、歌单、歌曲分页、详情和歌词进入 8 MiB 进程内 LRU 工作集后，保留期间的重复读取直接命中内存，不重复调用 API；被 LRU 淘汰后允许重新请求。
- 首次请求继续写入现有 Room 缓存；离线时保留现有磁盘回退能力。
- 同一缓存键的并发读取合并为一个上游请求，失败不能污染成功缓存。
- 单飞请求按等待者计数；最后一个等待者离开时取消上游 HTTP，取消不得转成失败缓存或污染其他仍在等待的调用者。
- 切换账号/服务器后不得读取其他命名空间的数据；注销和清缓存必须同步清理相应内存状态。
- 图片继续支持内存与磁盘命中，并合并同图并发下载；无效图片不能进入缓存。
- 已命中的图片更新磁盘 LRU 访问时间，写盘采用原子替换；清缓存期间完成的迟到下载不得重新写回已清命名空间。
- 图片磁盘档位是跨账号命名空间共享的设备级总上限，不得因账号数量线性增长；设置页显示并清理全局可回收占用，但保留账号与凭据记录。

### R2. 音频缓存预算

- 完全移除 Media3 持久音频磁盘缓存，不再创建或增长 `cacheDir/media`；升级后一次性清理旧音频分片。
- 保留 Media3 默认约 50 秒前向内存缓冲，并配置 15 秒回退内存缓冲；不引入小型磁盘 LRU 或离线下载。
- 原缓存档位改为图片磁盘缓存 32/64/128/256 MiB，默认 128 MiB；Room 资料缓存继续独立遵守 24 MiB 目标、32 MiB 物理上限。
- 设置页准确描述“图片缓存 + 资料缓存”的语义和当前占用，清理操作与显示结果一致，不再显示音频磁盘占用。

### R3. 漫游连续播放与播放状态机

- 漫游当前歌曲自然结束后自动、单飞地请求并播放下一首。
- 遥控器手动上一首/下一首与自然结束共用同一条漫游切换路径，连续按键不产生并发替换。
- 系统媒体键、MediaSession 控制和屏幕按钮在普通队列与漫游中必须遵循同一切歌语义。
- 退出漫游、切换普通队列、注销或断开时取消在途漫游请求，迟到响应不得覆盖当前队列。
- 漫游下一首加载失败时保留可重试状态，不清除用户登录凭据。
- 服务端漫游返回客户端当前无法直放的 CUE/不可用歌曲时，客户端单次最多检查 8 个窗口，并在 ID 为空、未变化或重复时立即停止，不能在同一节点永久失败。
- 退出漫游恢复进入前的普通队列、位置和分页上下文并保持暂停；进入前无队列则停止播放并回首页。
- 普通/漫游类型、漫游窗口、冻结队列、播放模式、当前项、位置和播放意图由播放层单一状态源拥有，并以版本化快照原子持久化；Activity 或进程重建后不产生半恢复状态。
- 所有播放快照只经一个按修订号排序的写入器落库；位置检查点不得晚到覆盖更新的模式、队列、退出漫游、普通队列替换或注销状态。
- 播放结束后再次按播放从当前曲开头恢复；播放位置超过 3 秒时按上一首先回到本曲开头，否则切到上一首；队尾和分页边缘不得无响应或跳错页。
- 滑动队列淘汰首尾页时同步修正页边界；往返浏览必须能够重新加载实际被淘汰的相邻页。

### R4. 播放队列与模式

- 播放操作条增加播放模式和队列入口，视觉层级参考用户提供的图片并适配现有播放器风格。
- 队列面板显示最多 250 首的已加载可播放活动队列数量、当前项、连续序号、歌曲名和歌手；打开时焦点落到当前项，当前项保持可见。
- 选择队列条目立即切换并播放；Back 先关闭队列面板，再隐藏操作条，再离开播放页。
- 普通队列支持顺序播放、列表循环、单曲循环和随机播放；默认列表循环，模式按钮按“列表循环 → 随机播放 → 单曲循环 → 顺序播放”循环切换并显示当前模式。
- 随机播放使用稳定的有效顺序并循环当前最多 250 首的已加载活动队列；切回顺序/列表模式恢复源队列顺序，不破坏分页游标。循环与随机不承诺遍历远端尚未加载或已淘汰的完整曲库。
- 模式切换必须立即作用于 Media3，队列快照恢复后保持一致；漫游模式不被普通队列循环规则截断。
- 队列分页增加/裁剪条目后，面板序号、当前项和焦点仍与实际 Media3 队列一致。
- 队列作为播放页右侧浮层而不是新导航页；漫游时隐藏普通队列与循环模式入口，只显示对当前漫游有效的操作。

### R5. TV 焦点与返回桌面

- 从方块/卡片进入网格、详情、歌曲列表或设置页后，数据就绪即聚焦阅读顺序中的第一个可操作位置。
- 从子页返回时保留原页面之前的焦点和滚动位置，不强制跳回首项。
- 在非根页面 Back 仍执行正常逐级返回；播放页继续遵循队列面板、操作条、页面的分层返回顺序。
- “我的”根视图 Back 先回首页；位于首页时第一次 Back 显示“再按一次返回桌面”提示，2 秒内第二次 Back 将任务退到桌面。
- 返回桌面只将 Activity 置于后台，不清队列、不停止当前音乐；超过 2 秒后再次 Back 重新计为第一次。

### R6. 切歌后的封面与歌词一致性

- 每次真实 MediaItem 切换，以及同一当前项的 ID/标题/歌手/格式/封面标识发生实质变化时，生成单调递增的 `presentationRevision`；这些字段必须从同一个已捕获的 `currentMediaItem.mediaMetadata` 投影，不能组合新旧歌曲字段。
- 当前曲展示请求以“账号命名空间 + mediaId + presentationRevision”为身份；新修订立即进入对应 Loading 状态并取消旧任务，任何迟到的旧修订结果不得发布到当前 presenter/UI。只有命名空间 generation 仍有效且至少还有一个合法等待者时，共享单飞结果才可正常填充缓存；否则不得写回内存或磁盘。
- API 层把协程取消传递给 OkHttp `Call.cancel()`，并始终重新抛出 `CancellationException`；取消不能显示为加载失败。
- 当前队列项缺少 `coverId` 时异步读取完整歌曲元数据补齐；音频播放不等待封面或歌词。
- 完整元数据、歌词和封面只对 I/O、408、429、5xx 等可重试的幂等瞬时失败自动重试 2 次，间隔 250 ms、750 ms；HTTP 401/鉴权错误、404、重定向、其他不可重试状态、成功空内容、合法无封面/无歌词和取消都只请求 1 次。歌词/封面的 404 或空内容映射为 Absent；完整元数据的 404/空内容保留 MediaItem 已有字段并结束为 Ready，不清空已知标题/歌手。
- 加载状态区分 Loading、Ready、Absent 和 RetryableFailure；自动重试耗尽后提供一个针对当前修订的重试操作，同一封面的另一首歌曲仍会建立新的切歌尝试。

## Acceptance Criteria

- [x] AC1：同一账号同一缓存键在仍被 8 MiB LRU 保留时连续或并发打开，只发生一次 API 请求；强制超过容量并淘汰后允许再次请求，且淘汰顺序可由单测验证。
- [x] AC2：切换账号后相同业务键不会命中旧账号内存缓存；网络断开时仍可读取合法的 Room 回退数据。
- [x] AC3：同一图片的暖内存/磁盘命中产生 0 次封面 HTTP 请求，并发冷命中只产生 1 次；跨账号文件总量不超过当前设备级档位，设置页占用与磁盘一致。
- [ ] AC4：播放完整歌曲后不存在新增媒体缓存目录或文件；单测断言 Media3 50,000 ms 前向上限与 15,000 ms 回退配置，设备上播放超过 20 秒后可回退 10 秒且不中断，旧音频缓存完成一次性清理。实现、配置测试与模拟器旧目录清理已验证；真实 NAS 媒体的 20 秒播放/回退 10 秒仍需具备媒体账号后手工确认。
- [x] AC5：漫游歌曲自然播放结束后自动开始下一首；自动切歌与快速手动切歌最多只有一个请求生效。
- [x] AC6：漫游切歌请求期间退出漫游或播放普通歌曲，迟到响应不会覆盖恢复后的队列。
- [x] AC6a：漫游进入、上一首和下一首遇到连续不可直放节点时最多检查 8 个窗口并检测循环；初次失败不改变普通播放，后续失败保留当前曲与可重试/退出状态，系统媒体键与屏幕按钮结果一致。
- [x] AC7：队列面板可从操作条打开，标题数量等于不超过 250 首的已加载可播放活动队列，行号连续且焦点定位当前曲；选择任意可见曲目后真实播放项与高亮同步。
- [x] AC8：顺序、列表循环、单曲循环、随机播放四种模式在活动队列的队首、队尾和应用内恢复后行为正确；随机顺序只有在服务确认接收完整且无重复的活动媒体 ID 后才生效。
- [x] AC8a：队列向两端跨越 250 首窗口并发生淘汰后，反向移动会加载正确相邻页，不跳页、不重复。
- [x] AC9：每种新页面首次进入时首个可操作内容获得焦点；返回原页面时原焦点与滚动位置得到恢复。
- [x] AC10：“我的”先返回首页；首页第一次 Back 仅提示，2 秒内第二次 Back 才返回桌面，音乐继续播放；超过时间窗后重新计为第一次。
- [x] AC11：相关模型、缓存、播放转换和 Compose 测试、完整 Gradle 单测与 lint 门禁通过；Android TV API 36 AVD 上的 Sideload/Store connected 测试实际运行通过，缺少可运行目标时不得标记完成。
- [x] AC12：可控测试执行 A → B → A 并逆序完成封面/歌词响应，只允许最新 A 修订显示；同封面失败后切到另一首会重新加载；最终瞬时失败可在不改变歌曲 ID 的情况下自动/手动恢复；同一当前项从缺失封面更新为已补齐封面时，旧请求也不能覆盖新修订。
- [x] AC12a：幂等资源可重试瞬时失败后成功最多发出 3 次请求；401、404、重定向、空/无效内容和取消各只发出 1 次。最后一个等待者取消会触发 `Call.cancel()`，两个等待者中只取消一个不会中止另一个的共享结果。

## Out of Scope

- 下载歌曲供离线长期播放。
- 跨设备同步播放队列或播放模式。
- 拖拽重排、队列删除或云端编辑歌单。
- 对超过 250 首的远端来源实现跨未加载/已淘汰页面的完整循环或全量随机遍历。
- 复刻网易云音乐的品牌视觉、私有业务逻辑或内部实现；仅参考其公开可观察的 TV 交互模式。
