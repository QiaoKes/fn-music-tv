# 架构边界解耦设计

## 边界

- `core:playback` 拥有播放所需的能力契约，不引用 `core:data` 的仓库或本地存储实现。
- `app` 作为装配层，用适配器把 `LocalStore`、`MusicRepository` 接到播放能力契约。
- `AuthenticatedAppCoordinator` 作为已登录业务编排边界，统一负责退出登录、缓存清理、播放停止和鉴权恢复。
- Compose 核心入口接收窄的 `AuthenticatedAppDependencies` 与动作契约，不直接依赖全量 `AppContainer`。

## 契约

- 播放持久化契约提供快照读取、写入、清理与账号队列读取所需的最小数据。
- 播放内容契约提供曲目准备、漫游窗口和队列分页能力，保持原取消与错误传播语义。
- 播放错误使用包含错误码和鉴权判断的类型，不再由 UI 解析 `errorCodeName` 字符串。
- 已登录编排器保持现有操作顺序；退出操作先停止并持久化播放，再结束会话。

## 兼容性

- 不改变数据库实体、快照 JSON、媒体协议或 Repository 的公开业务行为。
- 不改变 UI 布局、焦点、路由、文案及控制回调。
- 适配器只做参数映射，不引入缓存或额外状态。

## 回退

- 能力接口、应用适配器、UI 动作契约分别提交为独立代码边界；任一阶段失败可恢复到此前具体依赖，持久化数据无需迁移。
