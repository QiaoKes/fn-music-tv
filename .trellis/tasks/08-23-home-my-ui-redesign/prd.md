# 首页与我的页面 UI 改版

## Goal

将首页与“我的”页改造成统一、现代且适合 10 英尺观看距离的 Android TV 界面，解决顶部导航、账号信息和次级操作像散落文字的问题，同时保留现有音乐浏览、播放、账号切换和遥控器操作能力。

## Background

- 当前首页和“我的”页在 `app/src/main/java/com/fnmusic/tv/ui/AuthenticatedApp.kt:339` 共用 `LibraryTopBar`，但“首页 / 我的”以两个独立文字按钮展示，选中态与焦点态层级不清。
- 当前“我的”页在 `app/src/main/java/com/fnmusic/tv/ui/AuthenticatedApp.kt:704` 将“我的音乐”、`用户名 · 服务器名`、“设置”和“切换账号”拆成多个互相竞争的文字区域。
- 用户已选择方案 A：顶部胶囊分段导航、账号资料条；媒体列表最终采用左侧封面、右侧文字的横向卡片，以提高长名称可读性。
- 用户已选择首页动态封面稿 `docs/ui-redesign/design-a-home-dynamic.png`：随机漫游和收藏使用统一的三封面卡组，前者向外散开，后者向中心收拢。
- “我的”页视觉基准为 `docs/ui-redesign/design-a-my.png`。

## Requirements

### R1. Shared top navigation

- 首页与“我的”页必须继续共用一个顶部栏。
- 左侧保留现有正在播放胶囊及其打开播放器行为；没有媒体时留空，首页和“我的”都不显示常驻“回声台”文字。
- 右侧将两个独立按钮改为一个胶囊分段导航：当前页为珊瑚色实底，另一页为透明/弱化文字。
- 选中态与遥控器焦点态必须可区分；任意时刻只能有一个真实焦点目标。
- 切换页面、返回页面和触屏点击必须保留现有行为。

### R2. Home feature cards

- 首页第一内容行固定为两个等宽 16:9 风格功能卡：“随机漫游”和“收藏”。
- 两张卡使用相同的尺寸、圆角、标题位置、图标容器、暗色遮罩和封面规格。
- 随机漫游使用三张曲库封面向外错位展开，青绿色随机图标与深青背景表达发现和流动。
- 收藏使用三张收藏封面向中心对称收拢，珊瑚色心形图标与暖深色背景表达归档和偏好。
- 封面只作为装饰，不进入焦点树，不包含烘焙文字；标题和图标必须在暗色遮罩上保持远距离可读。
- 随机漫游继续使用现有 busy guard 与 `startRoam()` 行为；收藏继续打开收藏曲目路由。
- 没有封面 ID 的条目不得进入卡组；不足三张真实封面时只展示已有封面并重新居中排布，不能用首字或文字占位封面补满，也不能改变卡片尺寸或导致布局跳动。
- 功能卡封面首帧优先读取已解码或磁盘缓存；精确 Grid 图未命中时，允许先展示 Compact 缓存图并异步替换为 Grid 图。过渡期只能使用真实图片或中性深色底，不得显示标题首字占位。

### R3. Home playlist row

- 歌单与“全部歌单”继续位于第二行横向列表，使用真实封面、名称和类型信息。
- “全部歌单”使用深色虚线框与四宫格图标，不复用“全部歌曲”的曲库唱片插画。
- 歌单、歌手、专辑与曲库封面默认不显示珊瑚色描边；只有真实遥控器焦点出现时才显示珊瑚色焦点边框。
- 列表的拖动、触屏点击、D-pad 左右移动、向上返回相邻功能卡和焦点恢复行为必须保留。
- 首页重新进入时不得重复请求已成功加载的数据，不得闪回低清或占位封面。

### R4. My profile header

- 顶部分段导航已经标明“我的”页面，因此不再重复显示“我的音乐”大标题；资料条直接承接顶部导航。
- “我的”页无正在播放内容时，顶部左侧不显示“回声台”回退文字；有媒体时仍保留正在播放胶囊。
- 原 `用户名 · 服务器名` 文本替换为资料条：渐变首字母头像、用户名、带服务器图标的服务器徽章。
- 资料条外层保持透明，不显示贯穿页面的实色底面或边框；头像、身份信息和操作按钮维持稳定对齐。
- “设置”和“切换账号”改为资料条右侧的图标 + 文字幽灵按钮，默认弱化，焦点时使用珊瑚描边和明确反馈。
- 账号名称或服务器名称过长时必须省略而不是挤压操作按钮或溢出容器。
- 设置与切换账号继续调用现有路由 / `AuthenticatedAppActions`，不得复制清理、退出或登录协调逻辑。

### R5. My media bands

- 歌手、专辑和“全部歌曲”统一使用横向媒体卡：左侧为圆形头像或方形封面，右侧为名称和歌曲数 / 歌手等次要信息。
- 横向媒体卡默认背景与边框透明，聚焦 / 按压时才显示深灰表面和珊瑚描边；封面及其媒体语义底色不受影响。
- 真实封面、加载占位、失败占位、焦点预取、分页数据与点击进入详情行为必须保留。
- 歌手和专辑名称最多显示两行，超出后省略，不能与相邻项目重叠。
- “全部歌手”和“全部专辑”入口必须继续可通过横向滚动到达。
- 专辑下方保留第三个“音乐库”内容区及“全部歌曲”入口，首屏不为该入口压缩歌手、专辑或资料条。
- “全部歌曲”入口必须复用详情页的 `CollectionArtworkFallback.Collection` / `HomeArtworkKind.Collection` 图形，不再显示“全”字首字占位。

### R6. TV interaction and responsive behavior

- 所有命令继续使用项目的触屏兼容 TV `Button`，不得绕过现有单击去重与拖动滚动约束。
- 首次加载只在数据达到终态后请求第一个可操作项；从详情页返回必须恢复原焦点与滚动位置。
- 每个交互项使用稳定 `FocusRequester` 和显式上下左右邻接，不能依赖不确定的几何焦点搜索。
- 1920×1080 TV 视口必须无裁切、重叠或文字溢出；较小横屏视口使用明确断点或滚动，字体大小不得随视口缩放。
- 焦点反馈应由珊瑚描边、轻微缩放、表面色或阴影组成，不能引发布局位移。
- 包含缩放焦点项的 `LazyRow` / `LazyVerticalGrid` 必须预留至少 4dp 内容安全区，首尾项和“加载更多”聚焦时不得裁切描边或光圈。

### R7. Full artist and album pagination

- “全部歌手”和“全部专辑”必须复用同一个全屏分页框架，只由调用方提供标题、总数文案、数据加载器、稳定键和卡片内容。
- 1920×1080 视口每页固定 4 列 × 3 行，共 12 项；卡片沿用 My 页的左图右文尺寸、透明默认态与焦点态。
- 页面不得纵向滚动；标题、当前页 12 张卡片与底部分页器必须在标准 1920×1080 TV 视口同屏可见。
- 底部分页器由上一页图标按钮、`current / total` 页码和下一页图标按钮组成；边界按钮禁用，不显示“加载更多”媒体卡。
- 歌手与专辑 Repository 必须向现有服务端 `size` 参数直接传入 12，使服务端页与 TV 屏一一对应。响应缓存键必须包含页大小，防止旧的 50 项分页被当成 12 项分页。
- 当前 TV 页稳定后可异步预取下一个 12 项服务端页，但不得改变当前页、抢占焦点或显示“加载更多”卡片。
- 首次进入聚焦第一项；详情返回恢复界面页码与原卡片。末行向下进入可用分页按钮，分页器向上返回原列，连续翻页时焦点保留在分页器。

## Acceptance Criteria

- [ ] AC1: 首页与“我的”页均显示同一个胶囊分段导航，当前页和真实焦点状态清晰且不同时伪造两个焦点。
- [ ] AC2: 首页显示两张等宽功能卡；随机漫游封面向外展开，收藏封面向中心收拢，封面不足时布局仍稳定。
- [ ] AC3: 随机漫游、收藏、歌单、全部歌单、设置、切换账号、歌手、专辑和完整列表入口均保留原行为。
- [ ] AC4: “我的”页以资料条展示头像、用户名、服务器徽章、设置和切换账号，不再展示 `用户名 · 服务器名` 拼接文本。
- [ ] AC5: 歌手、专辑和全部歌曲使用统一横向卡片，长名称不重叠，加载/失败占位与真实封面尺寸一致。
- [ ] AC5a: 专辑下方保留“音乐库 / 全部歌曲”，入口图形与全部歌曲详情页一致且不显示“全”字占位。
- [ ] AC6: 遥控器可在顶部栏、功能卡、资料条操作和媒体行之间确定性移动；返回详情后恢复焦点和滚动位置。
- [ ] AC7: 触屏点击每次只触发一次，横向拖动仍滚动列表且不误触卡片。
- [ ] AC8: 1920×1080 模拟器截图与选定视觉稿的结构、层级和强调色一致，无裁切、重叠或布局跳动。
- [ ] AC9: 相关单元 / Compose / 设备测试及 sideload debug 构建通过。
- [ ] AC10: 全部歌手和全部专辑复用同一分页框架；1920×1080 每页 12 项、无纵向滚动，底部分页器可完整遥控器操作。

## Out of Scope

- 修改播放器、登录页、设置页内部布局或详情页视觉。
- 新增后端 API、数据库表或持久化账号字段。
- 修改随机漫游、收藏、播放队列或账号切换的业务语义。
- 将设计稿中的示例封面作为应用内固定资源发布；实际界面使用 NAS 数据与现有占位图形。

## Technical Notes

- App 会话恢复的品牌过渡页在“回声台”文字左侧显示正式 App Logo。
- `MusicRepository` 已提供 `playlists()`、`albums(page)` 与 `favoriteTracks(page)`，动态封面无需新增服务端能力。
- `LibraryRetainedStateStore` 已保存首页歌单、歌手、专辑和收藏路由数据；实现必须为首页预览明确数据所有权，避免路由移除时错误释放共享摘要。
- `.trellis/spec/frontend/android-tv-interaction.md:379` 定义了 Home/My 数据复用、焦点恢复、固定首行和远程封面约束，实现必须遵守。
