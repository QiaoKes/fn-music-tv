# 登录凭据与断网恢复

## Goal

让投影仪在应用重启、开机网络尚未就绪以及多个历史登录配置之间切换时，能够安全、稳定地恢复登录，避免重复输入账号、密码和安全码。

## Background

- 当前登录页默认启用“保持登录”，但只持久化服务端 token 和安全码；账号与密码不持久化。
- 当前最近服务器最多保留 5 条，选择历史记录只回填服务器地址和 HTTPS 状态（`app/src/main/java/com/fnmusic/tv/ui/FnMusicApp.kt:340-360`）。
- 当前密码在 API 边界执行一次 SHA-256 后发送（`core/data/src/main/kotlin/com/fnmusic/tv/core/data/api/TrimMusicApi.kt:33-38`）。持久化密码摘要后，自动登录必须直接发送该摘要，不能再次哈希。
- 当前启动恢复只执行一次；非鉴权类连接失败会保留 token，但仍发布退出状态并显示登录页，应用进程内不会再次自动恢复（`core/data/src/main/kotlin/com/fnmusic/tv/core/data/repository/SessionRepository.kt:69-93`、`app/src/main/java/com/fnmusic/tv/AuthenticatedAppCoordinator.kt:79`）。

## Requirements

- R1：启用“保持登录”后，持久化服务器连接信息、账号、密码的 SHA-256 摘要、安全码和服务端 token；不得持久化明文密码。
- R2：账号、密码摘要、安全码和 token 必须使用 Android Keystore 支持的加密存储，服务器显示信息可保留在应用私有偏好中。
- R3：每条登录历史按规范化服务器地址和账号联合标识；同一 NAS 可以保存多个账号，同一服务器与账号再次成功登录时更新原记录而不是新增重复项。
- R4：历史弹窗只参考用户提供截图的双行信息结构和交互：主信息显示账号，次信息显示服务器地址与 HTTP/HTTPS；当前选择项整行高亮，行尾提供单条删除，底部提供清除所有历史记录。颜色必须复用项目现有主题，不参考截图配色。
- R5：选择历史项后立即使用对应服务器、HTTPS、账号、密码摘要和安全码发起登录，不需要再次确认；登录失败时回到已回填表单并显示准确错误。密码输入框不得展示摘要或伪装成明文密码，而应显示“已保存密码”状态；用户输入新密码后改用新密码并在成功登录时更新摘要。
- R6：关闭“保持登录”时，仅在当前进程内保留登录所需凭据，不新增或更新持久化登录历史。
- R7：应用启动时优先使用已保存 token 恢复会话；服务端明确判定 token 无效后，使用同一历史配置中保存的账号、密码摘要和安全码重新登录并更新 token。
- R8：启动阶段遇到网络未就绪、NAS 暂时不可达或可重试服务端错误时，不进入普通登录表单、不删除任何凭据，并在应用内自动重试。
- R9：自动重试期间必须提供可见状态，并允许用户退出恢复流程、切换其他历史配置或手动登录，避免 NAS 长期离线时卡死。
- R10：服务端明确返回账号禁用、凭据错误或安全码错误时停止自动重试，保留可用于编辑/切换的历史资料并显示准确错误；不得无限提交错误凭据。
- R11：删除单条历史记录时删除该服务器和账号对应的全部持久化敏感凭据；清除所有历史记录时删除全部历史凭据，但不得误删当前未持久化的进程内会话。
- R12：升级现有安装时兼容当前已保存的单 token/安全码；旧 token 有效时继续恢复，旧数据中没有账号或密码摘要时不得要求不存在的数据。
- R13：敏感值不得写入日志、异常消息、测试快照或未加密偏好。

## Acceptance Criteria

- [ ] AC1：保持登录后强制结束并重启应用，无需重新输入即可恢复同一账号。
- [ ] AC2：加密存储中不存在明文密码；服务端收到的密码字段与用户原密码执行一次 SHA-256 的结果一致。
- [ ] AC3：同一服务器的两个账号能作为两条独立历史记录保存和切换；重复登录同一服务器与账号只更新原记录。
- [ ] AC4：历史列表按账号与“服务器地址（协议）”双行显示，当前项高亮；单条删除与清空全部会移除对应加密凭据。
- [ ] AC5：选择历史项后立即提交对应保存凭据，无需再次确认；失败时表单回填服务器、连接方式、账号和安全码，密码栏显示已保存状态并允许输入新密码覆盖。
- [ ] AC6：启动时前几次连接失败、随后网络恢复，应用在不重启进程且不展示普通登录表单的情况下自动进入已登录界面。
- [ ] AC7：持续离线时用户可以看到恢复状态并进入历史切换或手动登录，不会被无限加载页锁住。
- [ ] AC8：明确的 token 失效会触发一次已保存凭据重新登录；新 token 被安全保存，错误凭据不会无限重试。
- [ ] AC9：关闭保持登录后重启应用，不能使用该次登录的账号、密码摘要、安全码或 token 自动登录。
- [ ] AC10：从当前版本直接升级时，已有有效 token 仍可恢复；没有密码摘要的旧安装不会崩溃或产生错误的二次哈希请求。
- [ ] AC11：单元测试覆盖明文密码、已哈希密码、多账号历史隔离、删除与清空、旧数据兼容、可重试网络失败、鉴权失败和用户取消恢复。

## Out of Scope

- 修改 NAS 服务端的 token 有效期、会话数量或刷新协议。
- 跨设备同步登录凭据。
- 绕过 Android 系统清除应用数据、卸载应用或 Keystore 密钥丢失。
